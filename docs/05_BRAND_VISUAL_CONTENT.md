# Brand, Visual and Content Principles

## Brand foundation

**Name:** Rise Pals  
**Wordmark direction:** `risepals`  
**Domain:** `risepals.com`  
**Working tagline:** `Level up. Stay ready.`

## Brand idea

Rise Pals คือเพื่อนร่วมทางที่ช่วยให้ผู้ใช้เติบโตอย่างมีทิศทางในโลกงานที่เปลี่ยนเร็ว ไม่ใช่ผู้พยากรณ์ว่าจะตกงาน และไม่ใช่ครูที่ยืนตัดสินอยู่เหนือผู้เรียน

## Personality

- Future-facing แต่ไม่ใช้ศัพท์ AI จนล้น
- ฉลาด ตรง และมีหลักฐาน
- สนุกแบบผู้ใหญ่ หรือ **grown-up playful**
- กระตุ้นให้ลงมือทำโดยไม่สร้างความอับอาย
- เป็นเพื่อนร่วมคิด ไม่ใช่ mascot ที่พูดเหมือนเด็ก
- Optimistic realism: ยอมรับความเสี่ยงพร้อมแสดงทางออกที่ทำได้จริง

## Visual direction

- Motion ใช้อธิบายการเติบโต การเชื่อมโยง และ feedback
- Skill map ควรรู้สึกมีชีวิตและเปลี่ยนตามการลงมือทำ
- ใช้พื้นที่ว่าง typography และ hierarchy ให้ผลิตภัณฑ์ดู premium
- หลีกเลี่ยงภาพหุ่นยนต์ สมองเรืองแสง neon circuit และ visual cliché ของ AI
- หลีกเลี่ยง dashboard ที่เต็มไปด้วย gauge สีแดงซึ่งตั้งใจทำให้ผู้ใช้ตกใจ

## The Pals system

คำว่า Pals เปิดทางให้สร้าง companion system ประจำทักษะ แต่ระบบนี้ยังต้องผ่าน concept design ก่อนล็อก

แนวทางที่เป็นไปได้:

- Pal แต่ละตัวแทน competency หรือพฤติกรรมหนึ่งแบบ
- Pal ทำหน้าที่ guide, challenger หรือ reviewer ตามบริบท
- ผู้ใช้ค่อย ๆ ปลดล็อกความสามารถหรือความสัมพันธ์กับ Pal ผ่าน practice
- Character ต้องเหมาะกับ professional audience และใช้ได้ทั้งไทย/สากล

อย่าล็อกว่าต้องมี Pal สิบตัวจนกว่าจะทดสอบว่าช่วยให้ผู้ใช้เข้าใจ framework มากขึ้นจริง

## Image generation policy

- ภาพ raster, illustration, character และ marketing imagery ใหม่ทั้งหมดของ Rise Pals สร้างด้วย **GPT-Image-2**
- เก็บ prompt, date, model, intended placement และ revision note ของ asset ทุกชิ้น
- Visual consistency ต้องมาจาก art direction และ reusable prompt system ไม่ใช่สร้างภาพแยกกันโดยไม่มีระบบ
- UI layout, typography, charts, icons และ motion primitives ควรสร้างเป็น code/vector เพื่อ responsive behavior และ accessibility
- Generated imagery ต้องไม่เลียนแบบศิลปินที่ยังมีชีวิตหรือทำให้เข้าใจผิดว่าเป็นบุคคลจริง

## Content voice

### Do

- “งานเดิมของคุณอาจยังอยู่ แต่สิ่งที่บริษัทคาดหวังกำลังเปลี่ยน”
- “นี่คือทักษะที่ควรพัฒนาก่อน และเหตุผลที่ระบบแนะนำ”
- “คุณไม่จำเป็นต้องเก่งทุกอย่างพร้อมกัน เริ่มจากภารกิจนี้”
- แสดง risk พร้อม next action เสมอ

### Avoid

- “AI จะมาแย่งงานคุณแน่นอน”
- “คุณเหลือเวลาอีกเพียง X วัน” หากไม่มีหลักฐานรองรับ
- ตัวเลขเปอร์เซ็นต์ที่ไม่มี source หรือขอบเขต
- การทำให้ผู้ใช้รู้สึกด้อยค่าเพราะ score ต่ำ
- การใช้ urgency เพื่อซ่อนราคา บังคับต่ออายุ หรือทำให้ยกเลิกยาก

## Evidence block standard

ทุก statistical claim ต้องเก็บข้อมูลต่อไปนี้:

- Claim text
- Original source and direct URL
- Publisher
- Publication date
- Geography and sample/context
- What the data does and does not prove
- Date last verified
- Expiry/review date สำหรับข้อมูลที่เปลี่ยนเร็ว

หน้าเว็บควรเชื่อม risk claim กับ action ที่เกี่ยวข้องอย่างซื่อสัตย์ ไม่ใช้สถิติทั่วไปเพื่อกล่าวหาว่าผู้ใช้คนใดคนหนึ่งกำลังจะตกงาน
