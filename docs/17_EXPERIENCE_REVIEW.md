# ข้อเสนอปรับประสบการณ์ Rise Pals

วันที่ตรวจ: 15 กันยายน 2026 · เวอร์ชันที่ตรวจ: `2efe9a7`

เอกสารนี้เป็นผลตรวจและข้อเสนอ ยังไม่ได้เปลี่ยนพฤติกรรมของเว็บหรืออนุมัติฟีเจอร์รอบถัดไป

## ข้อสรุป

ควรลงทุนรอบถัดไปกับ **โจทย์ที่ทำให้ได้คิด และหน้าจบที่เห็นผลงานของตัวเอง** ก่อนขยายจำนวนบทเรียน ปัจจุบันหน้าตาและจุดเริ่มชัดขึ้นแล้ว แต่การตอบถูกยังไม่พอจะบอกว่าผู้เรียนใช้หลักนี้กับสถานการณ์ใหม่ได้

## สิ่งที่ตรวจพบจริง

ตรวจหน้าแรกและเส้นทางบทเรียนภาษาไทยบน production preview ที่ `127.0.0.1:3106` ด้วย Playwright ขนาดจอ 390 × 844 และเปิด reduced motion อ่านโค้ดคำถาม กติกา และเอกสารเป้าหมายผลิตภัณฑ์ประกอบ

| จุด | สิ่งที่พบ | ความหมาย |
| --- | --- | --- |
| จุดเริ่มบทเรียน | ปุ่มเริ่มอยู่ในหน้าจอแรก ตำแหน่งแนวตั้งประมาณ 584–633 พิกเซล | เก็บความชัดเจนนี้ไว้ |
| การแบ่งขั้น | เรื่อง → หลักฐาน → คำถามทีละข้อ | ลดสิ่งที่ต้องรับพร้อมกันได้แล้ว |
| กราฟ | แยก A 30%, B 8%, C ข้อมูลไม่ครบ | ช่วยให้เห็นปัญหาของข้ออ้าง และไม่ตีความข้อมูลที่หายเป็นศูนย์ |
| คำตอบ | เลือกตัวเลือกแรกทุกข้อ ผ่านครบทั้งสามเกณฑ์ ได้ตัวอย่าง 20 XP | มีรูปแบบคำตอบที่เดาได้ ต้องแก้คุณภาพโจทย์ |
| ขณะตอบ | หลักฐานอยู่ในส่วนที่ต้องกดเปิดอีกครั้ง | ควรทดลองให้ข้อมูลที่จำเป็นอยู่ใกล้คำถาม |
| หน้าจบ | มีคำอธิบายเกณฑ์สามก้อนและข้อความ XP; ปุ่มหลักเป็นลองอีกครั้ง/ล้างคำตอบ | ยังขาดผลงานสรุปและก้าวต่อไปที่มีความหมาย |
| หน้าแรก | ปุ่มหลักพาไปแบบลองตอบ 6 ข้อ ซึ่งยังไม่ให้ผลวินิจฉัยเฉพาะบุคคล | สำหรับเดโมตอนนี้ ควรทดลองให้ภารกิจที่จบเป็นชิ้นงานเป็นทางเข้าหลัก |

ข้อสังเกตเรื่องความสับสนและความน่าใช้เป็นการประเมินจากหน้าจอ ยังไม่ได้ยืนยันด้วยผู้ใช้เป้าหมาย การตรวจครั้งนี้ไม่ใช่ accessibility audit ครบทุกเกณฑ์หรือการวัดผลการเรียนรู้

## ลำดับที่แนะนำ

### 1. แก้โจทย์และคำตอบก่อน

- กระจายตำแหน่งคำตอบถูก พร้อมปรับตัวเลือกผิดให้เป็นความผิดพลาดที่คนทำงานมีโอกาสเลือกจริง
- ให้ความยาวและน้ำเสียงของตัวเลือกใกล้กัน ลดการเดาจากคำตอบที่ดูละเอียดที่สุด
- เพิ่มการเลือกหลักฐานหรือเหตุผลสั้น ๆ เพื่อแยกการเดาถูกออกจากการเข้าใจ
- ทดสอบด้วยสถานการณ์ใหม่หลังฝึก ไม่ใช้คำถามเดิมเป็นหลักฐานว่าฝึกสำเร็จแล้ว
- เปลี่ยนเนื้อหาผ่านเวอร์ชันบทเรียนใหม่และตรวจความสอดคล้องกับ rubric ตามระบบ publication เดิม

เกณฑ์รับงาน: ไม่มีรูปแบบเลือกตำแหน่งเดียวแล้วผ่านทั้งหมด และทุกคำตอบมีเหตุผลที่โยงกลับไปยังหลักฐานได้ การสลับลำดับอย่างเดียวไม่เพียงพอ

### 2. ให้ภาพเป็นส่วนของการลงมือทำ

เส้นทางต้นแบบที่เสนอ:

**เห็นสรุป AI → แตะข้อความที่น่าสงสัย → เลือกหลักฐาน → แก้สรุป → ดูก่อน–หลัง**

- เริ่มจากงานใกล้ตัว: “ช่วยเช็กสรุปนี้ก่อนส่งหัวหน้า”
- ให้แตะคำว่า “ทั้งสามทีม” หรือ “30%” แล้วเทียบกับข้อมูลทีม A/B/C
- ระหว่างตอบ แสดงหลักฐานฉบับย่อที่จำเป็นให้เห็น พร้อมเปิดเอกสารต้นฉบับได้
- ให้เลือกหรือประกอบประโยคสรุปที่ถูกต้อง โดยยังไม่ต้องพิมพ์ยาว
- ใช้สีร่วมกับข้อความและสัญลักษณ์ รองรับคีย์บอร์ดและการแตะ ไม่บังคับลากวาง

หลักการเปิดรายละเอียดเมื่อจำเป็นช่วยลดความซับซ้อน แต่ข้อมูลที่ต้องใช้บ่อยควรอยู่ตรงหน้า โดยเฉพาะขั้นตอนที่ต้องเทียบข้อมูลไปมา ตาม [NN/g: Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)

### 3. เปลี่ยนหน้าจบให้เห็นสิ่งที่ทำได้

แสดงผลงานหนึ่งใบก่อนรายละเอียดเกณฑ์:

> **คุณแก้สรุปนี้แล้ว**
>
> ก่อน: ทั้งสามทีมทำงานเร็วขึ้น 30%
>
> หลัง: ในข้อมูลทดลอง ทีม A เร็วขึ้น 30% ทีม B 8% ส่วนทีม C ยังสรุปไม่ได้ เพราะข้อมูลไม่ครบ
>
> ก่อนส่ง: ขอข้อมูลทีม C ให้ครบ และตรวจปัญหาที่ยังค้าง

ตัวอย่างนี้ใช้ข้อมูลสมมติของบทเรียนเดิม ต้องคงบริบท ขนาดตัวอย่าง และเอกสารประกอบให้เปิดดูได้

- ระหว่างฝึก ให้ feedback สั้น ๆ เชื่อมกับหลักฐาน เช่น “ทีม C ยังไม่มีข้อมูลครบ เลยยังสรุปรวมไม่ได้”
- ย่อผลเป็นสิ่งที่ผู้เรียนทำในโจทย์นี้ ไม่กล่าวอ้างว่าได้รับการรับรองทักษะ
- เก็บเกณฑ์ละเอียดและคำอธิบาย XP ในส่วนเปิดอ่านเพิ่ม
- ปุ่มหลักตอนจบพาไปลองกรณีใหม่ ส่วนลองซ้ำเป็นทางเลือกรอง
- ผลงานบนจอทำได้ก่อนระบบบันทึก การเก็บข้ามครั้งต้องออกแบบร่วมกับบัญชีและความยินยอมในรอบที่เหมาะสม

### 4. เชื่อมหน้าแรกกับภารกิจให้เป็นเส้นทางเดียว

ทดลองปุ่มหลัก “ลองเช็กคำตอบ AI” พาเข้าภารกิจนี้โดยตรงในเดโม เก็บแบบลองตอบเป็นทางเลือก และคงเป้าหมายระยะยาวของ assessment ตามกรอบ 8+2

เมื่อระบบประเมินมีผลที่นำไปเลือกบทเรียนต่อได้จริง ค่อยทดสอบอีกครั้งว่าทางเข้าแบบไหนเหมาะกับผู้ใช้ใหม่ ห้ามนำผลตัวอย่างคงที่ไปแสดงเสมือนเป็นผลจากคำตอบของผู้ใช้

### 5. เก็บรายละเอียดภาษาและหน้าจอ

| ปัจจุบัน | ตัวอย่างภาษาที่เสนอ |
| --- | --- |
| คุณควรสร้างร่องรอยการตรวจสอบแบบใดก่อน | จะเช็กคำตอบนี้ยังไง? |
| ความพอดีระหว่างข้ออ้างกับแหล่งข้อมูล | สรุปตรงกับหลักฐานไหม? |
| ก้าวถัดไปที่ปลอดภัย | ก่อนส่ง ต้องเช็กอะไรอีก? |

ภาษาอังกฤษควรเขียนใหม่ให้สั้นตามงานเดียวกัน เช่น “What would you check?” และ “What needs checking before you send it?” แล้วตรวจว่าความหมายของโจทย์ไม่เปลี่ยน

- ในหน้าบทเรียน ลดพื้นที่เมนูและ footer ให้เหลือสิ่งที่ช่วยเรียน กลับ หรือออกจากบทเรียน
- ให้ปุ่มหลักอยู่ตำแหน่งสม่ำเสมอ และมีข้อความอธิบายผลของการกด
- ใช้ motion สั้น ๆ เชื่อมจุดที่เลือกกับหลักฐาน หรือแสดงการแก้ประโยค รองรับ reduced motion
- ทดสอบจอเล็ก การขยายตัวอักษร คีย์บอร์ด และทั้งสองภาษา

แนวทาง [W3C: Help Users Understand What Things are and How to Use Them](https://www.w3.org/WAI/WCAG2/supplemental/objectives/o1-understandable/) สนับสนุนการทำให้จุดประสงค์ของหน้าและปุ่มเข้าใจง่าย เป็นคำแนะนำเสริม ไม่ใช่หลักฐานว่าเว็บผ่าน WCAG แล้ว

## ภาพและฟีเจอร์ที่ควรเพิ่มเมื่อมีหน้าที่ชัดเจน

- **SVG/กราฟ:** ใช้เทียบข้อมูล ชี้จุดผิด และเชื่อมหลักฐานกับข้ออ้าง
- **ภาพสร้างใหม่:** เหมาะเมื่อช่วยให้เข้าใจสถานการณ์หรือสร้างเอกลักษณ์ ต้องทำตามข้อกำหนดแหล่งที่มาของภาพในโครงการ
- **Animation:** ใช้แสดงผลของการลงมือทำ หลีกเลี่ยงการบังคับรอทุกครั้งที่เปิดหน้า
- **ความคืบหน้า:** ควรบอกว่าทำอะไรได้แล้วและควรฝึกอะไรต่อ เมื่อเส้นทางบันทึกพร้อม

พักการเพิ่มภาพตกแต่งจำนวนมาก คอร์สจำนวนมาก leaderboard และ AI chat ไว้ก่อน เพื่อให้รอบถัดไปตรวจได้ว่าภารกิจหลักช่วยผู้เรียนจริงหรือไม่

แนวทาง [IES: Organizing Instruction and Study to Improve Student Learning](https://ies.ed.gov/ncee/wwc/PracticeGuide/1) เสนอการใช้ภาพคู่คำอธิบาย การสลับตัวอย่างกับการแก้ปัญหา และคำถามที่ให้เหตุผล ใช้เป็นฐานออกแบบเบื้องต้นได้ แต่หลักฐานจากบริบทการศึกษาไม่ได้ยืนยันผลกับคนทำงานไทยหรือ Rise Pals โดยตรง

## รอบทดสอบที่เสนอ

ทำต้นแบบหนึ่งภารกิจให้จบ แล้วให้คนทำงานไทยประมาณ 5 คนลองทีละคน 15–20 นาที ใช้สถานการณ์สมมติ นี่เป็นข้อเสนอ ยังไม่ได้รับสมัครหรือติดต่อใคร

ให้ลองโดยไม่บอกตำแหน่งปุ่ม:

1. เริ่มภารกิจจากหน้าแรก
2. ชี้ว่าข้ออ้างตรงไหนยังสรุปไม่ได้ พร้อมเหตุผล
3. แก้ข้อความให้ตรงกับหลักฐาน
4. ลองกรณีใหม่ที่ใช้หลักเดียวกัน
5. บอกว่าจบแล้วได้อะไร และจะไปต่ออย่างไร

บันทึกจุดลังเล การย้อนกลับ เหตุผลที่เลือก และความเข้าใจ ไม่ใช้จำนวนคลิกหรือการจบเร็วเป็นตัวแทนการเรียนรู้

เป้าหมายเบื้องต้นเพื่อใช้ตัดสินใจรอบออกแบบ: อย่างน้อย 4 จาก 5 คนเริ่มได้เอง และอธิบายได้ว่าข้อมูลทีม C ที่หายไม่ได้แปลว่าผลเป็นศูนย์ ต้องตรวจการใช้หลักกับกรณีใหม่ด้วย จำนวนนี้ใช้ค้นหาปัญหา ไม่เพียงพอสำหรับกล่าวอ้างประสิทธิผลเชิงสถิติ
