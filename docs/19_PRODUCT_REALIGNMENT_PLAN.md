## 1. เป้าหมายผลิตภัณฑ์

**Rise Pals เป็นเพื่อนร่วมทางที่ช่วยคนหลากหลายอาชีพหาจุดที่ควรพัฒนา ฝึกกับเรื่องที่เกี่ยวข้องกับตัวเอง และสะสมหลักฐานว่าใช้ทักษะสร้างคุณค่าในงานได้มากขึ้น ในโลกงานที่เปลี่ยนไปกับ AI**

เริ่มจากภาษาไทยและรองรับภาษาอังกฤษ กรอบ 8 ทักษะ + 2 พฤติกรรมยังเป็นแกนของการออกแบบเนื้อหาและหลักฐาน ความสำเร็จปลายทางคือการนำไปใช้ในงานและต่อยอดโอกาส ไม่ใช่จำนวนบทที่เปิดหรือคะแนนจากการคลิก

วงจรผลิตภัณฑ์เดิมยังครบ: **เข้าใจบริบท → เลือกจุดเริ่ม → เรียน → ฝึก → แสดงสิ่งที่ทำได้ → ต่อยอด**

ข้อชี้แจงล่าสุดของ Jeff ขยายทางเข้าและบริบทจากกลุ่มออฟฟิศใน brief เดิม การไม่มีตำแหน่งงานในรายการต้องไม่ทำให้คนรู้สึกว่าใช้ Rise Pals ไม่ได้ ขณะเดียวกันต้องแสดงตามจริงว่าเนื้อหาใดพร้อมหรือยังไม่พร้อม

## 2. หลักตัดสินงานออกแบบ

1. **หนึ่งหน้ามีงานหลักหนึ่งอย่าง** พร้อมบริบทว่าอยู่ตรงไหน ทำไปเพื่ออะไร และต่อไปจะเกิดอะไร
2. **ให้คนเห็นตัวเองก่อนเห็นโครงสร้างของเรา** ไม่ต้องรู้จัก 8+2 หรือวินิจฉัยว่าตัวเองขาดทักษะใดจึงจะเริ่มได้
3. **ถามจากผลลัพธ์และเหตุการณ์จริง** แล้วค่อยเชื่อมทักษะตามพฤติกรรมที่เกี่ยวข้อง
4. **ทางเข้ากว้าง คำถามถัดไปตรงบริบท** ไม่ใช้คำถามกว้างชุดเดียวหรือสร้างแบบประเมินแยกทุกชื่ออาชีพ
5. **แต่ละกิจกรรมเชื่อมกลับไปยังเส้นทาง** ผู้ใช้รู้ว่าฝึกแล้วช่วยเรื่องของเขาอย่างไร
6. **ผลลัพธ์มีที่มา** แยกสิ่งที่ผู้ใช้เลือก สิ่งที่ตอบในโจทย์ และสิ่งที่ทำได้จากผลงาน
7. **เห็นความก้าวหน้าจากสิ่งที่ลงมือ** พร้อมกลับมาทำต่อและเปลี่ยนเป้าหมายได้

ความรู้สึกตลอดเส้นทางที่ต้องทดสอบ: **ที่นี่เข้าใจฉัน → ฉันรู้ว่าจะเริ่มตรงไหน → ฉันทำได้ดีขึ้น → ฉันอยากกลับมาทำต่อ**

## 3. เส้นทางผู้ใช้ใหม่

| จังหวะ | ผู้ใช้เห็นและทำอะไร | สิ่งที่ Rise Pals ต้องตอบให้ได้ |
| --- | --- | --- |
| เข้าเว็บครั้งแรก | เห็นคุณค่าหนึ่งใจความ และเลือกสิ่งที่อยากให้ดีขึ้น/สำรวจก่อน | ที่นี่ช่วยอะไรและเกี่ยวกับฉันอย่างไร |
| เข้าใจบริบท | เลือกบริบทที่เกี่ยวข้องเฉพาะเมื่อจำเป็น เช่น ทำงานกับทีม รับงานลูกค้า บริการหน้างาน ดูแลงานเอง | ถามสิ่งนี้เพื่อเลือกตัวอย่างที่ตรงกับฉัน |
| หาจุดเริ่ม | เล่า/เลือกเหตุการณ์ ผลกระทบ และลองโจทย์สั้นที่จำเป็น | เรารู้อะไรแล้ว ยังไม่รู้อะไร และควรเริ่มจากตรงไหน |
| เห็นเส้นทาง | ได้หนึ่งทางเริ่มพร้อมเหตุผล เป้าหมาย ภารกิจแรก และผลงานที่จะได้ | ทำไมทางนี้จึงเกี่ยวกับสิ่งที่ฉันเลือก |
| ฝึกครั้งแรก | เรียนแนวคิดเท่าที่ต้องใช้ ลงมือ รับคำแนะนำ แก้ไข และลองกรณีใหม่ | ฉันกำลังฝึกอะไร และสิ่งนี้ช่วยงานฉันอย่างไร |
| เห็นสิ่งที่ทำได้ | เห็นผลงาน/การตัดสินใจก่อน–หลัง ข้อเสนอแนะ และก้าวถัดไป | สิ่งที่ลงแรงไปให้อะไรกับฉัน |
| เก็บและกลับมา | เมื่อระบบรองรับ ชวนเก็บเส้นทางและผลงานด้วยบัญชี แล้วกลับมาทำต่อได้ | อะไรจะถูกเก็บ และกลับมาจะทำอะไรต่อ |

นี่เป็นจังหวะของประสบการณ์ ไม่ใช่ข้อบังคับว่าต้องถามครบทุกช่องหรือมีเจ็ดหน้าฟอร์ม ถ้ารู้บริบทแล้วให้ข้ามคำถามที่ไม่จำเป็น หนึ่งหน้ามีข้อมูลเฉพาะการตัดสินใจนั้น พร้อมทางย้อนกลับ

### ตัวอย่างหน้าต้อนรับสำหรับทดสอบ

> **อยากให้การทำงานของคุณดีขึ้นตรงไหน?**  
> เริ่มจากเรื่องของคุณ แล้วค่อย ๆ หาทางพัฒนาทักษะไปด้วยกัน
>
> - อยากให้งานราบรื่นขึ้น
> - อยากรับมือเครื่องมือหรือวิธีทำงานใหม่
> - อยากเตรียมตัวสำหรับโอกาสถัดไป
> - ยังไม่แน่ใจ ขอสำรวจก่อน
>
> เลือกจุดเริ่ม → ลองฝึก → เห็นทางต่อ

ใช้คำอธิบายแบรนด์สั้น ๆ ให้รู้ว่าเป็นการพัฒนาทักษะสำหรับโลกงานยุค AI คำถามข้างต้นเป็นทางเข้าเบื้องต้น ไม่ใช่ข้อวัดความสามารถหรือคำถามจากงานวิจัยที่เสร็จแล้ว ต้องทดสอบว่าคนเข้าใจคำแต่ละตัวเลือกตรงกันหรือไม่ก่อนล็อก copy

ไม่แสดงแผนที่คะแนนเต็มหน้า รายชื่อทักษะทั้งหมด และคำอธิบายระบบตั้งแต่ต้น ให้สำรวจเพิ่มเติมได้ ส่วนจำนวนขั้น/เวลา/การสมัคร/ค่าใช้จ่ายต้องบอกเมื่อเกี่ยวข้องก่อนผู้ใช้ตัดสินใจ โดยไม่แต่งเวลาประมาณหรือสัญญาการบันทึกที่ยังทำไม่ได้

### ทางเข้าและสถานะพิเศษ

- คนที่ยังไม่มีปัญหาชัดเจนสามารถสำรวจหรือเตรียมรับการเปลี่ยนแปลงได้ ไม่ต้องยอมรับปัญหาที่ทีมสมมติขึ้น
- เปิดจากลิงก์บทเรียน: เห็นว่าบทนี้ช่วยเรื่องอะไร อยู่ในเส้นทางไหน และไปต่ออย่างไร
- มีหลายลักษณะงาน: เลือกบริบทได้มากกว่าหนึ่ง เปลี่ยนได้ และไม่ต้องระบุตำแหน่งตายตัว
- ตัวเลือกไม่ตรง: มีทางเลือกอื่น/ข้าม/ตัวอย่างกลาง โดยไม่ตีความว่าความสามารถต่ำ
- หลักฐานไม่พอ ผลเสมอ หรือไม่มีบทที่ตรง: บอกข้อจำกัดและให้เลือกทางสำรวจต่อ ไม่สร้างผลเฉพาะบุคคลปลอม
- ผู้ใช้ที่กลับมา: เข้า **เส้นทางของฉัน** เห็นสิ่งที่ทำค้างและขั้นถัดไป ไม่เริ่มคำถามต้อนรับใหม่ทุกครั้ง

## 4. ทำให้สมจริงโดยไม่จำกัดอาชีพ

หน่วยออกแบบโจทย์คือ **เหตุการณ์ + ข้อจำกัด + การตัดสินใจ + ผลกระทบ** อาชีพช่วยเลือกบริบท แต่ใช้ตัดสินระดับทักษะหรือความต้องการแทนผู้ใช้ไม่ได้

ตัวอย่างสมมติสำหรับทดสอบแนวทาง:

| เรื่องที่อยากให้ดีขึ้น | บริบทต่างกัน | สถานการณ์ที่จะค้นหา/ตรวจสอบกับผู้ใช้ |
| --- | --- | --- |
| ลดงานที่ต้องกลับมาแก้ | คนในทีม / ผู้รับงานอิสระ | เกณฑ์รับงานไม่ตรงกัน / ลูกค้าขอแก้เกินขอบเขตที่คุย |
| เข้าใจกันก่อนเริ่มงาน | งานบริการ / งานหน้างาน | ลูกค้าคาดว่าจะได้อีกอย่าง / ข้อมูลก่อนลงมือยังไม่ชัด |
| งานเดินต่อได้ | งานองค์กร / ดูแลกิจการเอง | ต้องรอข้อมูลหลายฝ่าย / หลายเรื่องชนกันจนเลือกไม่ถูก |
| รับมือการเปลี่ยนแปลง | ทุกบริบทที่เกี่ยวข้อง | เครื่องมือหรือขั้นตอนใหม่เปลี่ยนสิ่งที่ต้องทำและสิ่งที่ถูกคาดหวัง |

ถามต่อจากเรื่องที่เลือก เช่น “ครั้งล่าสุดเกิดอะไรขึ้น?” “กระทบอะไรที่สุด?” “ตอนนั้นมีข้อจำกัดอะไร?” โดยแสดงทีละจังหวะตามที่จำเป็น ความถี่ เวลา ต้นทุน และผลที่ไม่ทราบต้องระบุว่าไม่ทราบ

อย่าสรุปปัญหาหน้างานเป็นจุดอ่อนส่วนตัวทันที สาเหตุอาจเป็นทรัพยากร กติกา อำนาจตัดสินใจ หรือระบบองค์กร ต้องแยกสิ่งที่ผู้ใช้ฝึกแล้วเปลี่ยนได้ออกจากข้อจำกัดเหล่านั้น

คำถามที่จะใช้จริงต้องมีบัตรที่มา: **บริบท / เหตุการณ์ / ผลกระทบ / วิธีที่ทำอยู่ / ข้อจำกัด / แหล่งข้อมูลและวันที่ / สถานะหลักฐาน / พฤติกรรมที่จะฝึก**

สถานะหลักฐานแยกเป็น สมมติฐานของทีม → เรื่องเล่าจากผู้ใช้ → ตัวอย่างงานหรือหลายแหล่งประกอบ → ผลการทดลองกิจกรรม การสัมภาษณ์และตัวเลขจากกลุ่มเล็กไม่ใช่หลักฐานความถี่ของปัญหาทั้งตลาดหรือประสิทธิผลการเรียน

## 5. การแนะนำเส้นทางและกรอบ 8+2

ลำดับเหตุผลของคำแนะนำต้องเปิดดูได้:

**ผู้ใช้เลือกสิ่งที่อยากเปลี่ยน + บริบทที่เกี่ยวข้อง + หลักฐานจากโจทย์/ผลงานที่มี → จุดเริ่มที่เสนอ → ผลงานที่ตั้งใจให้ทำได้**

- ถ้ามาจากเป้าหมาย ให้ใช้ข้อความเช่น “เริ่มทางนี้เพราะคุณอยากลดงานแก้ซ้ำ” ไม่แสดงว่าเป็นจุดอ่อนที่วัดได้แล้ว
- หากมีผลจากโจทย์ ให้ระบุข้อสังเกตและขอบเขตเฉพาะที่รองรับ ผู้ใช้เปลี่ยนเส้นทางหรือทักท้วงได้
- แผนที่แสดง 8 ทักษะหลักและ +2 แยกกัน ได้แก่ คิดวิเคราะห์/ตรวจข้อมูล คิดเป็นระบบ เปิดรับการเรียนรู้ เข้าใจอารมณ์และผู้อื่น ฟื้นตัว/ปรับตัว ใฝ่รู้ ตัดสินใจอย่างรับผิดชอบ เล่าเรื่องเชิงกลยุทธ์ และสองพฤติกรรมคือคิดแบบเจ้าของกับลงมืออย่างทันสถานการณ์
- ค่อยเติมหลักฐานจากการฝึก ไม่บังคับประเมินทุกด้านรวดเดียว และไม่เรียกชุดคำถามสั้นว่าประเมินครบ 8+2 หากยังไม่รองรับ
- “ยังไม่มีข้อมูล” ต้องไม่แสดงเป็นศูนย์หรืออ่อนทักษะ การจบบทไม่เปลี่ยนเป็นเปอร์เซ็นต์ความเชี่ยวชาญอัตโนมัติ
- รูปแบบโจทย์ต่างบริบทอาจใช้หลักคิดเดียวกัน แต่ต้องตรวจความเทียบเคียงก่อนเปรียบเทียบคะแนนข้ามกลุ่ม

สามแนวเนื้อหาที่มีศักยภาพจากงานเดิมคือ ตรวจข้อมูล คิดเป็นระบบ และสื่อสารเพื่อการตัดสินใจ ทั้งหมดเป็นสมมติฐานสำหรับเลือกเส้นทางนำร่องจากผลค้นหาปัญหา ไม่ล็อกหลักสูตรก่อนฟังผู้ใช้ เป้าหมายระยะยาวยังครบ 8+2

## 6. ศูนย์กลางหลังเริ่มใช้: เส้นทางของฉัน

หน้าหลักหลังเริ่มใช้มีสี่ส่วนตามลำดับ:

1. **เป้าหมายของฉัน:** เรื่องที่เลือกและเหตุผลของเส้นทาง เปลี่ยนได้
2. **วันนี้ทำอะไร:** ภารกิจเดียวที่เหมาะจะทำต่อ พร้อมสิ่งที่จะได้
3. **ฉันเดินถึงไหน:** แสดงขั้นที่ทำแล้ว/กำลังทำ/ถัดไป พร้อมสถานะจริง
4. **สิ่งที่ฉันทำไว้:** ผลงาน การแก้ไข และ feedback ที่เปิดกลับมาดูได้

เมนูหลัก: **เส้นทางของฉัน / ทักษะ / ผลงาน / บัญชี** รายละเอียดกรอบ วิธีประเมิน และที่มามีให้เปิดอ่านในจุดที่เกี่ยวข้อง

ภารกิจทุกบทต้องเชื่อม **เป้าหมาย → แนวคิด → ลงมือ → feedback → ปรับ → ลองกรณีใหม่ → ผลงาน → ก้าวต่อไป** ผลงานอาจเป็นแผนภาพงาน ข้อตกลงก่อนเริ่มงาน สรุปพร้อมแหล่งข้อมูล หรือข้อเสนอที่ใช้ตัดสินใจ รูปแบบขึ้นกับพฤติกรรมที่ต้องฝึก

โครงร่าง การฝึกพร้อมคำแนะนำ การลองเอง และหลักฐานจากงานจริงต้องแยกสถานะให้ชัด การแชร์หรือใช้ต่อภายนอกอยู่ภายใต้การควบคุมของผู้ใช้และความพร้อมของระบบ

## 7. บุคลิก ภาพ และ motion

แนวที่เสนอจาก brief: **ฉลาด อบอุ่น สนุกแบบผู้ใหญ่ เห็นการเติบโต และเคารพจังหวะของผู้ใช้** รายละเอียดตัวละครยังเป็นงานออกแบบที่ต้องทดสอบ

- ครั้งแรก: ภาพช่วยอธิบายว่าจะทำอะไรและได้อะไร ไม่ต้องดูข้อมูลหลายกล่องก่อนเริ่ม
- เลือกเส้นทาง: แผนที่เปิดส่วนที่เกี่ยวข้องพร้อมเหตุผล คงมุมมองรายการที่อ่านและใช้คีย์บอร์ดได้
- ตอนฝึก: ภาพ/แผนผังเป็นสิ่งที่ใช้ตัดสินใจได้ ไม่เพิ่มภาพที่แย่งความสนใจจากโจทย์
- ตอนจบ: เห็นผลงานก่อน–หลังและขั้นที่เปลี่ยนตามผลจริง
- กลับมา: เห็นงานที่ทำไว้และก้าวถัดไป ความรู้สึกต่อเนื่องมาจากประวัติจริง
- Pals: เป็นผู้ช่วยบอกบริบท ชวนคิด และชี้ก้าวต่อไป เริ่มทดสอบบทบาทหนึ่งแบบก่อนจำนวนตัวละคร ไม่มีเหตุให้สร้าง AI chatbot แยกทุกทักษะตั้งแต่ต้น
- ไทย/อังกฤษกระชับเป็นธรรมชาติ ไม่มีความหมายสำคัญที่ต้องอาศัยสีหรือ motion อย่างเดียว รองรับ reduced motion และทำภาพใหม่ตามนโยบายของ Jeff

## 8. ลำดับงานพร้อมเงื่อนไขผ่าน

| รอบ | งานและสิ่งที่ส่งมอบ | เงื่อนไขผ่านก่อนขยาย |
| --- | --- | --- |
| 1. เข้าใจคนและปัญหา | ค้นหาเหตุการณ์จากคนหลายบริบท บัตรที่มาปัญหา แผนผังความต้องการ และสมมติฐานเส้นทาง | ปัญหามีที่มา แยกข้อจำกัดระบบกับสิ่งที่ฝึกได้ ไม่มีการใช้คำพูดจากกลุ่มเดียวแทนทุกอาชีพ |
| 2. เห็นประสบการณ์ทั้งเส้นทาง | ต้นแบบคลิกได้ตั้งแต่เข้าเว็บจนกลับมาทำต่อ หลายบริบท รวมคนไม่รู้จุดเริ่มและคนเปิดจากลิงก์บทเรียน | คนที่ไม่รู้จัก Rise Pals เข้าใจคุณค่า รู้ว่ากำลังทำอะไรและทำไปเพื่ออะไร หาเรื่องที่ตรงได้โดยไม่ฝืนตอบ |
| 3. ทำเส้นทางนำร่องให้มีคุณค่า | เนื้อหา โจทย์ rubric ผลงาน และเหตุผลเลือกเส้นทางที่ผ่านการทบทวน ทั้งสองภาษา | ทุกกิจกรรมเชื่อมเป้าหมายงานและทักษะได้ ผู้ใช้ลองสถานการณ์ใหม่ได้ ผลลัพธ์ไม่เกินหลักฐาน |
| 4. เชื่อมการใช้ต่อเนื่อง | บัญชี เป้าหมาย แผนฝึก บทเรียน ประวัติผลงาน และกลับมาทำต่อ บนระบบเดิม | บันทึก/กลับมาได้จริง จำกัดเจ้าของ ส่งซ้ำไม่เพิ่มผลซ้ำ และประวัติผูกกับเวอร์ชันถูกต้อง |
| 5. ทดลองวงจรครบและปรับ | ทดสอบความเข้าใจ การเลือกทาง การนำไปใช้ และการกลับมา พร้อมตรวจ accessibility/การทำงาน | มีหลักฐานว่าผู้ใช้เข้าใจทางของตัวเองและได้คุณค่าจากการฝึก ปัญหาของกลุ่มย่อยไม่ถูกกลบด้วยผลรวม |

การวิจัยผู้ใช้เริ่มในรอบ 1 และทดสอบต้นแบบในรอบ 2 ไม่รอจนเชื่อมระบบเสร็จ งานโครงต้นแบบที่ใช้ข้อมูลสมมติทำระหว่างค้นหาปัญหาได้ แต่ต้องติดป้ายสมมติฐานและปรับจากหลักฐานก่อนล็อกเนื้อหา

แผนทดสอบใช้รอบเล็กหลายรอบ ครอบคลุมงานในองค์กร งานอิสระ/กิจการ งานขาย/บริการ และงานหน้างานตามบริบทที่เลือกนำร่อง เริ่มด้วยผู้ทดลองที่ไม่เคยอ่าน brief ถามให้เล่าเหตุการณ์ก่อนเห็นแนวคำตอบของทีม และทดสอบหน้าแรกโดยไม่บอกชื่อปุ่มให้กด เก็บทั้งคำอธิบายและพฤติกรรมแยกบริบท จำนวนผู้ร่วมวิจัยและเวลาแต่ละรอบกำหนดจากขอบเขตจริง ไม่อ้างกลุ่มเล็กว่าแทนทุกอาชีพ

การศึกษาเนื้อหาและผลการเรียนรู้แยกจากการทดสอบ usability การกดจบได้หรือชอบภาพไม่ใช่หลักฐานว่าทักษะดีขึ้น ยังไม่มีการติดต่อผู้ร่วมวิจัยหรือผลสัมภาษณ์ในรอบวางแผนนี้

## 9. สิ่งที่ใช้ต่อและงานระบบที่ต้องเพิ่ม

| ใช้ต่อจากฐานปัจจุบัน | ปรับ/เพิ่มตามแผน |
| --- | --- |
| ภาษา component งานภาพพื้นฐาน และชุดทดสอบ | โครงหน้าต้อนรับและหน้าหลักที่ยึดเส้นทางของผู้ใช้ |
| กรอบ 8+2 และข้อมูล profile ที่มีอยู่ | บริบทหลายแบบ เป้าหมายและความต้องการที่เลือกเปลี่ยนได้ |
| ระบบ assessment/result และการอธิบายผล | นิยามเนื้อหาเวอร์ชันใหม่ การสำรวจเป็นช่วง และกติกาแนะนำตามหลักฐาน |
| บทตรวจข้อมูลแบบโต้ตอบ | วางเป็นหนึ่งบทในเส้นทาง พร้อมตัวอย่างบริบทที่ตรวจแล้ว |
| private attempts/progress และ evidence lifecycle | แผนฝึก เวอร์ชันของแผน เหตุผลการเลือก และประวัติผลงานที่เชื่อมกัน |
| Supabase + Netlify + GitHub | เชื่อมและตรวจ hosted setup เมื่อถึงขั้นใช้งานจริง |

ข้อเท็จจริงปัจจุบัน: แบบประเมินเดิมครอบคลุมสองทักษะหลักและสองพฤติกรรม; `/learning` แสดงวงจรบทเดียว; ภารกิจสาธารณะ v2 เป็น local prototype ไม่บันทึกผล; hosted setup ยังไม่พร้อม ข้อมูล profile, persisted result, lesson attempts และ private evidence มีโครงโค้ดอยู่แล้ว แต่ไม่ได้เท่ากับเส้นทางใหม่พร้อมใช้

การเปลี่ยนบทเรียน การวัด และการบันทึกต้องออกเวอร์ชันที่ตรวจสอบได้ รักษา published v1 และประวัติเดิม ภารกิจสาธารณะ v2 ต้องผ่าน publication/persistence integration ก่อนใช้เป็นบทส่วนตัวที่บันทึกได้ ไม่ย้ายคำตอบเดโมเข้าบัญชีเงียบ ๆ

งานนำร่องกับข้อมูลจริงต้องมีการเก็บข้อมูลเท่าที่จำเป็น การยินยอมและสิทธิ์เข้าถึงตามการใช้งาน ไม่มีการสร้างทรัพยากรเสียเงิน เปลี่ยน DNS หรือ deploy จากการอนุมัติให้วางแผนครั้งนี้

## 10. จุดตรวจภาพรวมก่อนเรียกว่าได้ทิศทางที่ต้องการ

- คนใหม่เข้าใจว่าเว็บช่วยเรื่องงานและการพัฒนาตนเองในโลกยุค AI โดยไม่ต้องอ่านกรอบทั้งหมด
- คนหลายบริบทเห็นความเกี่ยวข้องกับตนและมีทางไปต่อเมื่อคำถามไม่ตรง
- แต่ละหน้ามีงานหลักชัดเจน พร้อมเหตุผลและความเชื่อมโยงกับขั้นถัดไป
- เหตุการณ์และผลกระทบที่ใช้มีที่มา ไม่มีการสมมติว่าทุกปัญหาเกิดจากผู้ใช้ขาดทักษะ
- เส้นทางต่างกันตามความต้องการและหลักฐานที่เกี่ยวข้อง ไม่บังคับทุกคนเข้าบทเดียว
- ผู้ใช้รู้ว่าฝึกเพื่ออะไร เห็นสิ่งที่ทำไว้ และกลับมาทำต่อได้
- ความก้าวหน้าแยกสิ่งที่จบกับสิ่งที่แสดงความสามารถในขอบเขตนั้นได้
- สิ่งที่ยังไม่ประเมินหรือเนื้อหาที่ยังไม่พร้อมแสดงตามจริง

## 11. ระยะต่อไปและสิ่งที่ยังไม่ล็อก

เมื่อวงจรนำร่องมีคุณค่า ค่อยขยายเนื้อหาและการวัดครบ 8+2 ตามหลักฐาน เพิ่มโค้ช การเรียน online/live/onsite สมาชิก และบริการทีม ก่อนเชื่อมผลงานกับโอกาสงานอย่างอธิบายได้และผู้ใช้ควบคุมได้

ยังไม่ล็อกรายชื่อคำถามสุดท้าย จำนวนตัวละคร ชุดเส้นทางนำร่องทั้งหมด ราคา หรือวันส่ง ต้องใช้ผลค้นหาปัญหา การทบทวนเนื้อหา และความพร้อมบริการประกอบ ไม่เพิ่ม job board หรือหลักสูตรจำนวนมากก่อนวงจรหลักทำหน้าที่ได้
