## D-017 — PostgreSQL baseline and trusted RLS context

- **Date:** 2026-08-03
- **Status:** Accepted by Project Codex after RP-TURN-010 closeout
- **Decision:** Establish one PostgreSQL/Drizzle baseline migration for only the nine authorized identity, consent and versioned definition tables. Force RLS on user-owned tables and resolve ownership through a validated transaction-local user UUID set only by trusted server code. The normal application role must be separate from the migration/table-owner role and must be neither superuser nor `BYPASSRLS`.
- **Reason:** Database invariants and tenant isolation need evidence from PostgreSQL itself before durable user workflows are authorized. A disposable loopback-only PostgreSQL instance with synthetic users tests the migration without selecting or creating production infrastructure.
- **Consequence:** Version rows begin as drafts, publish only after database validation, may retire only through a status-only transition and are immutable while published or retired. The eight exact core weights total 10,000 basis points; multipliers remain unweighted; consent is append-only; unsafe foreign-key deletion fails closed; JSON content requires an explicit schema version. Ordered parent locks protect OLD and NEW framework/assessment parents from reparent and publication races. Normal application runtime receives only the non-owner `DATABASE_URL`; migration/test tooling alone receives the separately decoded-role-validated owner URL. Application credentials cannot migrate schema or bypass RLS, and browser code must never receive a database credential or control the trusted context directly.
- **Open:** Production provider/placement, supported deployed major version, credentials and rotation, TLS path, pooling, backups/restore, retention/deletion, monitoring and operational access remain separate decisions. RP-TURN-010 does not authorize authentication, profiles, assessment response persistence, scoring persistence, lesson progress, XP, proof storage, CI, a Windows service or deployment.

## D-021 — Deterministic trusted content publication boundary

- **Date:** 2026-08-22
- **Status:** Accepted by Project Codex for RP-TURN-014 synthetic alpha at reviewed implementation head `e4572c02c4bbfa25f9e88b34d79d96b600da224f`
- **Decision:** Git remains the only pilot lesson authoring source. Publish repository-local trusted MDX plus metadata, practice, rubric, proof and source records through a deterministic build-time JSON registry rather than a database import. The exact immutable identity is lesson key plus semantic version, with strict UTF-8/LF per-file SHA-256 and an ordered aggregate digest. An independently Git-reviewed seal authorizes each exact identity/digest and is never rewritten by the publication command; generated outputs cannot authorize their own replacement. `source-verification-practice@1.0.0` is operationally `published` for synthetic alpha while separately `prototype-unvalidated`; publication is not an efficacy, credential, employability, external-validation or production-release claim.
- **Reason:** The accepted bilingual lesson needs a reviewable content provenance and safe stale/conflict gate before persistent learning progress. A tracked registry preserves Git review, exact historical bytes and static rendering without adding content tables, an authoring service or executable MDX.
- **Consequence:** Exact-pinned build-only AST tools parse MDX into controlled JSON and never compile or execute it. Runtime imports only the validated registry through a server-only boundary and maps six allowlisted identifiers to fixed local lesson sections. ESM, expressions, raw HTML, unsafe links, images, spreads, event handlers, unknown components, traversal, symlinks, ambiguous IDs and incomplete/expired evidence fail closed. Identical publication is idempotent; source mutation or removed/altered sealed entries in either generated output fail without changing output bytes. External-evidence dates are calendar-exact and require `publicationDate <= lastVerifiedDate < reviewExpiryDate`; expiry uses the current UTC instant, with an injectable deterministic test instant and no time-dependent generated field.
